# Carsharing analytics

Локальное PHP-приложение для анализа каталога и состояний автомобилей каршеринга.

Возможности:

- каталог: вид транспорта → марка → модель;
- ручная диагностика гостевых API-выдач без записи данных;
- ручной сбор снимка свободных и занятых автомобилей;
- хранение текущего состояния и полной истории наблюдений;
- фиксация переходов между статусами;
- рейтинг автомобилей и моделей по числу подтверждённых аренд и возвратов.

## Требования

- PHP 7.3 или новее с расширениями PDO MySQL, cURL и mbstring;
- MySQL 5.7 или новее;
- локальный веб-сервер, например OpenServer.

## Установка

1. Разместите файлы в каталоге сайта OpenServer.
2. Для чистой установки импортируйте `schema.sql`. Существующую базу обновляйте через `server_update.sql` или `migrate.php`.
3. Создайте отдельного пользователя MySQL для базы `carsharing_app`.
4. Укажите параметры подключения через переменные окружения:
   - `VORON_DB_HOST`
   - `VORON_DB_PORT`
   - `VORON_DB_NAME`
   - `VORON_DB_USER`
   - `VORON_DB_PASS`

По умолчанию приложение читает эти значения из файла `.env` в корне проекта. Файл исключён из Git, а прямой HTTP-доступ к нему закрыт через `.htaccess`. Путь к другому конфигурационному файлу можно задать переменной `CARSHARING_APP_ENV_FILE`. Пароли не следует добавлять в PHP-файлы, SQL-дамп или Git.

## Обновление существующей базы

Перед обновлением сделайте резервную копию базы. Затем из каталога проекта выполните:

```bash
php migrate.php --status
php migrate.php
```

Первая команда только показывает ожидающие изменения. Вторая применяет их в правильном порядке. Выполненные миграции записываются в `schema_migrations`, поэтому команду безопасно запускать повторно. Дамп рабочей базы хранится только локально и исключён из Git.

Если на сервере удобнее работать через HeidiSQL, откройте базу `carsharing_app`, загрузите или вставьте целиком файл `server_update.sql` и выполните его. Это объединённый повторно запускаемый вариант тех же миграций для MySQL 5.7 и новее.

## Страницы

- `index.php` — каталог транспорта;
- `diagnostic.php` — ручная проверка одного API-запроса без записи;
- `collector.php` — ручной веб-запуск и CLI-сбор снимка для cron;
- `analytics.php` — текущие показатели и рейтинг аренды.
- `daily_catalog_update.php` — подготовленный CLI-скрипт ежедневного обновления каталога и обнаружения новых автомобилей без записи событий аренды.
- `update_intervals` — единый справочник интервалов: `vehicle_statuses` для статусов автомобилей и `vehicle_catalog` для моделей и марок; значения хранятся в минутах.

Ежедневный скрипт получает каталог через `/v6/catalog.php/getCatalog/{random}`, затем проверяет гостевые списки свободных и занятых автомобилей. Уже существующие автомобили не имеют отметки «Новинка». Только впервые добавленный автомобиль получает `vehicles.new_until` на три дня; последующие обновления этот срок не продлевают.

Первое наблюдение автомобиля является исходной точкой и не считается заказом. Событие аренды создаётся только после реального перехода между двумя снимками.

## Cron на сервере

`collector.php` поддерживает защищённый ручной веб-запуск и отдельный CLI-режим для cron. Пример расписания для серверного пути `/var/www/maot.ru/data/www/areal-spik.ru/` находится в `crontab.example`: статусы собираются каждые 30 минут, каталог моделей и марок обновляется ежедневно в 00:00. Перед установкой расписания проверьте путь к PHP командой `command -v php` и наличие каталога `/var/www/maot.ru/data/logs/`.

## Структура базы

- `vehicle_types`, `brands`, `models` и таблицы связей — каталог;
- `vehicles` — конкретные автомобили и текущее состояние;
- `collector_runs` — журнал запусков;
- `vehicle_status_history` — снимки состояний;
- `vehicle_status_events` — только изменения состояния;
- `statuses` — справочник нормализованных статусов.

`schema.sql` предназначен для чистой установки. Файлы `migration_*.sql` содержат последовательные изменения существующей базы, а `migrate.php` проверяет и применяет их.
